# 4 路最终归并与 postings 优先编码 — 2026-09-08

**保留本轮实现。** 相比已启用 32 KiB 块和后置压缩的串行最终归并，vLLM 完整构建从 **1127.85 ms 降至 792.44 ms（−29.7%）**，四倍 vLLM 从 **4494.66 ms 降至 2899.00 ms（−35.5%）**。8 × 8 MiB 未触发外排，延迟基本持平。峰值 RSS 中位数变化不超过 0.54 MiB。

## 实现与并发范围

旧路径把多个有序 run 串行归并成完整的原始记录文件，再重新读取它编码索引。新路径在最后剩余 2–32 个 run 时，按记录数取最多 4,096 个样本，选出 gram 四分位边界，再对各 run 二分定位。最多 4 个任务分别归并自己的键范围，同一个 gram 完整归属一个任务，跨 run 重复在本任务内消除。

任务边归并边做差分 varint 编码，写出压缩 postings 分片及每键 12 字节的元数据（gram、内联 ID 或压缩长度）。任务结束后先按键范围拼接 postings，再按已知键数写 lookup 目录和正文，沿全局键流每 128 键分块。分片边界不会额外产生部分 lookup 块，最终仍是字节一致的版本 4 格式。

这里的 4 指**最终归并任务数**，复用已有 Rayon 池。提取仍为本机默认 8 个生产线程，排序仍使用默认 10 线程 Rayon 池；最终归并开始时提取线程已经结束。池线程少于 4 或 gram 分布无法拆出 4 个非空范围时，会降低实际并发。两组 vLLM 的每次插桩构建均执行 4 个归并编码任务。

超过 32 个 run 的中间归并仍分组执行；单个 run 已知键数，直接流式编码；完全没有外排时直接从排序数组编码。新路径省去最终**原始记录**文件的写读，仍保留压缩分片及键元数据的写读和最后的顺序拼接。

## 对照方法

基线为[32 KiB 实验](chunk-32k-2026-09-08.md)保留的最终源码和二进制。本轮两版均使用 256 MiB 工作预算、相同提取/排序配置。本机为 macOS arm64、Apple M5、10 个逻辑 CPU、24 GiB 内存。语料为：8 个 8 MiB 文件，共 64 MiB / 527,380 行；vLLM 6,835 个可搜索文件、82.38 MiB；四倍语料 27,340 个文件、329.53 MiB。

每版本、每语料预热 2 次、计时 7 次，另做 3 次 `/usr/bin/time -l` 峰值 RSS 测量。固定随机种子交错版本，每次新建索引，使用热文件缓存。索引和查询校验在计时结束后进行，编译、测试及阶段插桩测量不与 release 基准并发。首次启动的预热异常值不进入中位数。

## 完整构建、内存与临时写入

耗时取 7 次中位数；RSS 列为各次进程峰值再取 3 次中位数。

| 语料 | 旧版 ms | 新版 ms | 延迟变化 | 旧版 RSS MiB | 新版 RSS MiB |
|---|---:|---:|---:|---:|---:|
| 8 × 8 MiB | 124.08 | 125.08 | +0.8% | 62.83 | 62.30 |
| vLLM | 1127.85 | 792.44 | −29.7% | 212.48 | 212.89 |
| vLLM × 4 | 4494.66 | 2899.00 | −35.5% | 217.11 | 217.13 |

新版所有 RSS 样本的最高值为 **217.97 MiB**。工作预算仍为 256 MiB，不是进程 RSS 硬限制。归并读缓冲最坏为 `4 × 32 × 64 KiB = 8 MiB`，加编码缓冲等主要工作区低于 9 MiB，复用此时已释放的提取与排序预算，仍适配最低 16 MiB 参数。[预算边界](../../docs/index-build-memory-budget.md)

7 次计时范围：8 MiB 组旧/新为 122.78–128.60 / 122.36–132.13 ms；vLLM 为 1122.54–1150.65 / 784.74–803.82 ms；四倍语料为 4440.81–4655.76 / 2865.58–2949.47 ms。8 MiB 组的变化约 1 ms，范围重叠，且没有进入修改的外排路径。

| 语料 | 初始 run 数，旧 → 新 | 临时总写入中位数 MiB，旧 → 新 | 变化 |
|---|---:|---:|---:|
| 8 × 8 MiB | 0 → 0 | 0 → 0 | — |
| vLLM | 2 → 2 | 540.96 → 395.37 | −26.9% |
| vLLM × 4 | 7 → 7 | 2165.97 → 1355.43 | −37.4% |

临时写入统计包含原始 run，以及新版压缩分片和键元数据；不包含最终索引、文件系统元数据及分配块取整。上述语料没有中间归并，输入 run 和全部分片共存时达到临时文件峰值，因此峰值逻辑大小等于临时总写入。最终 lookup/postings 大小和哈希保持一致。

## 阶段耗时

另对三个语料使用隔离源码插桩，每版本预热 2 次、计时 7 次。单位为 ms，取各阶段中位数。下面两组会触发最终归并；旧版归并包含完整原始输出 run 的写出，旧版编码包含重新读取该 run。新版归并与 postings 编码已融合，无法直接把两项分别一一对应。

| 阶段 | vLLM 旧 | vLLM 新 | vLLM × 4 旧 | vLLM × 4 新 |
|---|---:|---:|---:|---:|
| 提取与收集 | 437.90 | 433.70 | 2172.61 | 2150.61 |
| 排序 | 155.81 | 154.56 | 656.20 | 650.77 |
| 排序后去重 | 38.28 | 38.75 | 161.85 | 162.33 |
| 初始 run 写入 | 91.21 | 90.00 | 384.41 | 371.73 |
| 串行最终归并 | 308.12 | — | 1511.70 | — |
| 旧流式编码 | 193.33 | — | 602.81 | — |
| 分区采样与定位 | — | 2.83 | — | 3.46 |
| 4 路归并并编码，墙钟 | — | 101.25 | — | 502.39 |
| postings 拼接 | — | 5.45 | — | 30.04 |
| lookup 生成 | — | 77.10 | — | 68.95 |
| 归并与编码合计 | 500.68 | 185.86 | 2123.70 | 604.52 |
| 构建函数总计 | 1117.89 | 798.88 | 4529.22 | 2972.71 |

“合计”先对每次构建相应阶段求和，再取中位数，因此不必等于表中阶段中位数之和。排序、去重、初始写入与提取收集部分嵌套，不能把整张表相加。完整延迟结论以无插桩 release 表为准。

归并与编码合计分别下降约 **62.9% / 71.5%**，提取、排序、去重基本持平。4 个归并编码任务的线程累计墙钟分别为 398.74 / 1993.11 ms，约为并行阶段墙钟的 3.94 / 3.97 倍，表明这两组的任务充分重叠；累计值不是用户等待时间，也不是纯 CPU 时间。gram 生成与输出的提取线程累计耗时为 1784.60 → 1783.30 / 7451.07 → 7414.31 ms，符合这部分没有修改的预期。

本轮同时采用融合编码和 4 路并行，未单独测量各改动的独立贡献。与早期“增加内存预算后耗时上升 55% / 95%”的报告不是同轮基线，不能直接将历史百分比相减。
