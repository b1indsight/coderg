# 两字节查询扩展为三字节索引片段：vLLM 实测

当前决策（2026-09-07）：**暂缓采用。** 用户认为扩展后的候选仍多，决定当前不加入这项优化；以下保留实验方法和原始结果。

实验结论：将两字节字面量与可能相邻的一个字节组合，复用已有三字节索引，并继续用原始正则验证候选文件，能降低这组查询的延迟。索引格式、索引文件内容和磁盘占用保持不变。此次结果来自隔离的临时原型，未加入正式搜索实现。

本次比较当前 release 二进制、两种扩展原型及 rg。vLLM commit 为 `569adb5a9780f9c02d22a6b29826acf711512356`，6,835 个文本文件、82.38 MiB；Apple M5 / 24 GiB，环境与[完整正则 benchmark](vllm-regex-suite-2026-09-07.md)相同。运行开始于 `2026-09-07T07:50:42.083556+00:00`。

每个查询/模式先核对完整匹配行输出及退出码，再预热 3 次、计时 31 次。每轮随机交错全部模式和查询，种子 20260907，使用热缓存。输出包含路径、行号、完整匹配行，计时重定向到 `/dev/null`。13 个查询 × 7 种模式，共 2,821 个计时样本；所有查询输出均与原版和 rg 一致。

两种原型的工作方式：

- `all`：对两字节词 `if`，查询 `Xif` 和 `ifX`，X 枚举所有 256 个字节值，共 512 个三字节键。所有 posting list 取并集。
- `boundary`：对于精确形式 `\bif\b`，额外利用词边界，排除相邻 ASCII 字母、数字和下划线，保留全部非 ASCII 字节作为保守候选；两侧合计 386 个键。无词边界的查询仍用 512 个键。
- 文件首尾：左右两侧取并集，保证有前邻或后邻即可；恰好只有两字节的可搜索文件从 manifest 单独加入候选。候选仍由原正则匹配，扩展字符不进入最终匹配表达式。

只补空格会漏掉制表符、换行、标点和文件边界。Unicode 词边界也不能简单视为空格：原型保留所有高位字节，最后由原来的 Unicode 正则决定是否匹配。哈希碰撞和不完整的单侧边界筛选只会增加候选，不会据此确认匹配。

安全性验证覆盖两层。Rust 过滤测试对 `if`/`qx`、带/不带词边界，穷举左右邻字节 0..255 的组合，并检查文件首尾和 Unicode 上下文；通过。另构建真实索引，在 1,047 个文件上对 4 个查询 × 2 种扩展做完整输出比较，覆盖空文件、一字节文件、恰好两字节文件、邻字节 1..255，以及空白、标点、Unicode 上下文；8 项均与原版逐字节一致。详见 [edge-checks.json](data/vllm-short-expansion-2026-09-07/edge-checks.json)。

原型范围限定为大小写敏感的两字节 ASCII 字母数字字面量，以及精确的 `\bXX\b` 形式。它不代表 `-i`、任意组合正则或一字节查询已经得到支持。一字节补成三字节会有更大的组合数，需要单独设计。

正式实现需要为短词扩展设置独立且完整的预算：当前通用查询上限为 128 个不同索引键，直接把 386/512 个备选放入现有流程会触发放弃过滤；只截取前 128 个则可能漏匹配。本原型在独立路径完整枚举最多 512 个键，用候选位标记合并 postings，没有改动通用预算。建议保留这种独立的有界路径，并按解析后的正则结构识别可用字面量和边界。

测试复用了此前生成的现有索引，未重建 vLLM 索引。运行前后生产二进制、原型二进制、源码、全部索引文件 SHA-256、vLLM commit 和工作区状态均保持一致。本次没有测量冷缓存和峰值内存；正式采用后仍应复跑完整查询集合确认更广范围的表现。

复现方式：将当前源码复制到独立目录，应用 [prototype.diff](data/vllm-short-expansion-2026-09-07/prototype.diff)，为包设置独立名称 `coderg-short-probe` 并同步 Cargo.lock 的根包名称，用 release profile 构建。完整原型文件为 [prototype-search.rs](data/vllm-short-expansion-2026-09-07/prototype-search.rs)，原版相对 HEAD 的差异为 [baseline-source.diff](data/vllm-short-expansion-2026-09-07/baseline-source.diff)。

将 [benchmark.py](data/vllm-short-expansion-2026-09-07/benchmark.py) 顶部的源码、语料、索引、二进制路径改为本地路径，依次执行 `python3 benchmark.py check`、`python3 benchmark.py bench --iterations 31 --warmup 3`。原型通过 `CODERG_SHORT_PROBE=all` 或 `boundary` 选择扩展方式；`CODERG_SHORT_TRACE=1` 输出候选和规划诊断，仅用于未计时检查。

过滤单测命令为 `cargo test --release --locked short_probe_tests::expanded_filter_covers_byte_contexts_and_document_edges`（在原型目录运行）。真实索引边界校验入口为 [edge_check.py](data/vllm-short-expansion-2026-09-07/edge_check.py)。[checks.json](data/vllm-short-expansion-2026-09-07/checks.json) 保存各命令、环境、完整输出摘要和候选诊断。
