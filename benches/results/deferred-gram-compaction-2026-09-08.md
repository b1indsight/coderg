# gram 后置压缩对照 — 2026-09-08

**保留后置压缩实现。** 同一组 8 × 8 MiB 文件的完整构建延迟下降 **11.4%**，峰值 RSS 中位数增加 **1.27 MiB**；vLLM 和四倍语料分别改善 **1.6% / 1.3%**，内存增量为 **2.13 / 0.20 MiB**。最终索引字节和查询结果一致。

## 对照范围

基线是已经启用乘法扩散和直接输出 Vec 的当前版本，见[此前两项优化](gram-extraction-2026-09-08.md)。本轮只改变块内去重使用的键及压缩时机：

```text
之前：生成 u64 → 压缩 u32 → HashSet<u32> 乘法扩散并查重 → 输出 u32
之后：生成 u64 → HashSet<u64> 直接使用已混合哈希查重 → 成功后压缩并输出 u32
```

`GramHasher::write_u64` 直接返回已有哈希；其他使用 `u32` 的集合/映射继续使用原乘法扩散。输出 Vec、8 字节关联记录及 V4 磁盘格式继续使用 `u32` 键。新的集合以完整 64 位键判等，因此不同完整哈希压缩后可能输出重复键，交由后续排序/归并去重。

本轮同时减少重复 gram 的压缩操作、消除块内查重的乘法扩散，并改变哈希表键宽及桶定位分布；没有单独隔离这些变化，不能把全部加速归因于省掉一条乘法。

## 测量方法

- 同一台 macOS arm64 主机，10 个逻辑 CPU；256 MiB 构建预算，默认线程配置。这三组语料均使用 8 个提取线程，排序使用默认 Rayon 池。
- 无插桩 release 二进制分别保存，每版本、每组预热 2 次、计时 7 次，另做 3 次 `/usr/bin/time -l` 峰值 RSS 测量。版本顺序按固定随机种子交错，每次新建索引，使用热文件缓存。
- 计时不包含后续索引校验及查询。RSS 测量与常规计时分开；基准期间没有并发运行编译、测试或采样。
- 8 MiB 组包含 8 个文件、共 64 MiB / 527,380 行；vLLM 为 6,835 个可搜索文件、82.38 MiB；四倍语料为 27,340 个文件、329.53 MiB。路径和 Git 状态保存在原始数据中。

## 工作缓冲区与正确性

单块仍为 16 KiB。较长 gram 的两端权重严格大于内部所有权重；将它归属到权重较小的一端（相等时任选一端），另一端必然是该方向最近的不小于它的权重。因此，每个字节对最多对应左右各一个较长 gram，加上所有 trigram，整块生成数小于字节数的三倍。16 KiB 块少于 49,152 个键，`u64` 集合、扩容峰值、紧凑输出及队列结果仍由原有每线程 8 MiB 预留覆盖。代码预算说明及现有随机/重复输入测试已更新。

新增实际碰撞样例：三个字节 `27 55 22` 与 `29 67 68` 的完整哈希分别是 `c7f2ddeab4852c9e`、`5387f88020f009f4`，压缩后同为 `7377f174`。测试覆盖后置压缩输出重复键，去重后仍与原 `u32` 提取集合相同。

- **72 次 release 构建 + 36 次插桩构建**全部通过索引 lookup/postings 逐字节哈希和文档元数据一致性检查。
- **30 次查询**的完整输出哈希及退出码一致，覆盖短查询回退、长字面量、大小写与分支。
- `cargo test --offline`：50 个测试通过；`cargo fmt --check`、`cargo clippy --offline --all-targets -- -D warnings` 通过。
- 最终工作区 release 二进制与实测新版 SHA-256 完全相同。插桩仅在临时源码副本中进行。
