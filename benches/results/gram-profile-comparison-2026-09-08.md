# gram 优化前后分项对照 — 2026-09-08

**在 8 × 8 MiB 合成文件组上，优化前后的提取总成本基本持平。** HashSet 插入/查重仍约占提取工作三分之一；旧版单独的集合转 Vec 成本，在新版移入了提取过程中的 Vec 追加、扩容等操作。排序、排序后去重和编码的变化也很小。

本轮补齐旧版在同一组 8 MiB 文件上的三段调用栈采样，与[当前版本三段采样](hashset-share-2026-09-08.md)对照；另补当前版本的 64 × 1 MiB 采样，与[最早的采样](build-bottlenecks-2026-09-08.md)交叉核对。旧版是两项 gram 优化之前的 256 MiB 构建实现，新版包含哈希分布优化和直接输出 Vec。

## 对齐采样口径

本轮把“提取工作”统一定义为生成 gram、块内 HashSet 操作和生成输出 Vec，包括旧版独立的 HashSet 转 Vec 步骤。不同版本的编译内联会改变栈帧边界，因此同时识别提取工作线程中的 hashbrown 插入子树，不要求它总是显式挂在 `hashes_for_document` / `hashes_for_chunk` 栈帧下。按调用树计算互不重叠的自身样本，再归入类别；父子样本不重复累计。

**此前新版的 34.4% 使用较窄的“显式提取函数子树”口径；补计外层函数帧未显示的插入调用后，本轮为 36.2%。** 这属于分类范围完善，没有重新修改产品代码，也不能解释为 HashSet 突然变慢。

以下为 **8 × 8 MiB** 的提取工作采样占比，旧版和新版各三段、每段请求 5 秒、间隔 1 ms。

| 类别 | 旧版 | 新版 |
|---|---:|---:|
| HashSet 插入/查重及其子调用 | 35.18% | 36.18% |
| 其他可辨识 HashSet/hashbrown 操作 | 0.30% | 0.36% |
| gram 扫描、哈希及内联输出操作 | 57.76% | 63.46% |
| 独立的 HashSet 转 Vec | 6.75% | 0% |

第三行是提取函数中的其余代码，**不等于纯 gram 扫描时间**。新版的 Vec 追加大多内联在这个函数里；“独立转 Vec 变成零”仅表示这条调用路径消失，不表示生成输出数组已经没有成本。三个百分比变化不能单独证明任一操作的绝对耗时变化。

64 × 1 MiB 的旧/新提取采样结果也相近：HashSet 插入为 35.63% / 36.19%，扫描、哈希及内联输出为 57.04% / 63.48%，独立集合转 Vec 为 7.03% / 0%。这组各只有一段采样，作为辅助核对，不与 8 MiB 样本混合计算。

## 相同语料的阶段计时

另在旧、新两个独立插桩版本上交错运行，每版本、每语料预热 2 次、测量 7 次，完整构建新索引。插桩版本不与采样或编译并发运行。这里与最早一次测量的机器瞬时状态不同，因此比较同一轮的新旧数字，不跨轮相减。

8 MiB 组中，**8 个提取线程的 gram 生成与输出累计墙钟时间为旧版 847.03 ms、新版 847.58 ms**。旧版先逐次相加 `gram_hash + chunk_collect` 再取中位数，新版直接取已合并的 `gram_hash`；两者覆盖同一段工作。它们是各线程累计值，包含调度影响，不能当成整个构建延迟。

下表为主线程关键阶段的墙钟时间中位数，单位 ms。“其中”属于父阶段，不能重复相加。

| 阶段 | 旧版 | 新版 |
|---|---:|---:|
| 构建函数总计 | 153.22 | 150.34 |
| 目录与文件状态收集 | 2.92 | 2.98 |
| 提取与收集 | 117.90 | 116.76 |
| 其中：主线程等待提取结果 | 108.12 | 106.06 |
| 其中：收集记录到缓冲区 | 8.59 | 8.73 |
| 提取结束后处理 | 31.93 | 31.41 |
| 其中：排序 | 22.47 | 22.51 |
| 其中：排序后去重 | 3.54 | 3.55 |
| 其中：统计不同 gram 数 | 1.28 | 0.91 |
| 其中：最终编码与写入 | 4.59 | 4.47 |
| manifest 写入与缓存处理 | 0.09 | 0.09 |
| 临时写入 / 归并 | 0 / 0 | 0 / 0 |

提取线程累计打开文件为 0.64 / 0.76 ms，累计读取为 10.64 / 9.37 ms，累计通道发送为 13.58 / 11.86 ms；这些不是主线程阶段，不能再加到上表。

插桩版本用于分解成本，最终性能结论仍以此前[无插桩 release 对照](gram-extraction-2026-09-08.md)为准：8 MiB 组为 148.97 → 150.07 ms，基本持平；vLLM 和四倍语料分别改善约 6.3% 和 6.2%。本轮没有重新对 vLLM 拆分 CPU 热点，不能将合成文件上的占比推广到它。

## 其他过程的采样

为了观察排序等部分，下面采用另一个明确的分母：完整进程调用栈中，扣除已识别的条件变量、信号量、锁等待及让出线程等等待栈后的样本。它仍包含 I/O 与调度影响，**不代表严格 CPU 时间或完整构建墙钟比例**。

| 类别 | 旧版 8 MiB 组 | 新版 8 MiB 组 |
|---|---:|---:|
| HashSet 插入/查重 | 28.74% | 29.55% |
| 其他 HashSet 操作 | 0.25% | 0.29% |
| gram 扫描、哈希及内联输出 | 47.19% | 51.83% |
| 独立集合转 Vec | 5.52% | 0% |
| 可辨识的 Rayon 排序调用 | 15.60% | 15.72% |
| postings 后处理，如去重/统计/编码 | 0.67% | 0.75% |
| 文件系统调用 | 1.38% | 1.15% |
| 收集记录 | 0.13% | 0.09% |
| 元数据处理 | 0.01% | 0.02% |
| 其他 | 0.50% | 0.60% |

编码等串行阶段的墙钟占比会高于它在所有线程样本中的占比；线程累计样本与端到端关键路径衡量的是不同事情。

## 验证和复现

两组语料、两个插桩版本的 **36 次构建**全部通过索引段字节与文档元数据一致性检查。采样驱动只增加重复全量构建循环：旧版 8 MiB 共运行 180 次，当前 1 MiB 共运行 90 次，两个进程均正常结束；采样期间的构建不计入延迟数据。正式源码和 release 二进制未改变。
