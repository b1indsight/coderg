# 默认按行匹配与 vLLM 查询性能 — 2026-09-09

默认搜索改为逐行验证后，vLLM 的 TODO 注释查询从 **103.65 → 29.89 ms**，排除刷新后从 **90.75 → 14.22 ms**，后者约快 **6.38 倍**。数字查询的 no-refresh 延迟减少 **29.0%**，但仍略慢于 rg。普通固定字符串基本持平；按行匹配不会让所有查询都明显加速。

## 改动

候选文件仍按原有索引筛选、完整读取，并按文档 ID 输出。最终匹配以 LF 为界，保留 CR，用 `is_match` 判断每个实际文本行，不枚举行内所有匹配。换行通过 `memchr_iter` 按需定位，不再建立全文件行起点数组、二分定位每个匹配或通过 `BTreeSet` 去重。Rayon 使用 `map_init` 克隆正则，供各执行任务使用。`-l` 在每个文件的第一个匹配行处停止。

`\s` 和 `(?s)` 都不能跨越 LF；空文件和末尾 LF 后的位置不产生额外行。目前没有跨行搜索选项。这是匹配语义与执行路径的整体改动，性能差值不能全部归因于“禁止跨行”这一个因素。字符串生成和逐行 `println!` 输出路径保持原实现。

## 方法与正确性

- 基线为干净提交 `202da2f` 的 release 构建；候选为本次工作区改动，双方使用同一 Cargo release 配置。代码差异与二进制、源码 SHA-256 已归档。
- 冻结 vLLM 提交 `569adb5a9780f9c02d22a6b29826acf711512356`，6,835 个文本文件、82.38 MiB；测量结束时 Git 工作区仍干净。
- 使用基线在语料外构建的新索引，两个版本共用。索引格式不变，测量期间 manifest 校验和保持不变。
- macOS arm64、10 个逻辑 CPU，未设置 `RAYON_NUM_THREADS`。版本信息与绝对路径见原始 JSON。
- `benches/regex_suite.py` 的 30 项查询，对修改前/后默认模式、修改前/后 no-refresh 模式和 rg 五种命令随机交错预热 3 轮、计时 31 轮，种子 `20260909`。热文件缓存，stdout 指向 `/dev/null`，包含独立进程启动、匹配与输出成本。编译和测试不与计时并发。
- 完整输出校验在计时外完成，只去掉路径开头的 `./` 并排序，保留重复行；校验退出码。候选默认和 no-refresh **30/30 与 rg 一致**。旧版有 `async_def` 和 `blank_lines` 两项已知差异，不能把这两项的前后耗时当成相同输出的性能比较。
- 单元及集成测试共 **57 项通过**；新增覆盖跨行空白、dotall、行锚点、CRLF、空文件、末尾换行、计数和最大匹配行数。格式与 diff 空白检查通过。

## 同轮耗时

单位为毫秒，均为 31 次中位数。

| 查询 | 旧默认 | 新默认 | 旧 no-refresh | 新 no-refresh | rg |
|---|---:|---:|---:|---:|---:|
| TODO 注释：`^[ \t]*#.*\b(TODO\|FIXME)\b` | 103.65 | 29.89 | 90.75 | 14.22 | 68.50 |
| 数字：`\b[0-9]{2,4}\b` | 166.21 | 119.02 | 146.28 | 103.81 | 96.57 |
| 忽略大小写 TODO/FIXME | 30.97 | 30.29 | 16.15 | 14.68 | 68.69 |
| 固定字符串 `get_tensor_model_parallel_world_size` | 26.99 | 26.68 | 11.31 | 11.35 | 66.59 |
| 短词 `\bif\b` | 102.91 | 104.15 | 88.59 | 86.90 | 93.50 |
| 空行 `^[ \t]*$`（旧版输出不同） | 183.98 | 183.24 | 170.49 | 168.01 | 102.58 |

新默认模式仍慢于 rg 的是数字、短词和空行查询；no-refresh 模式仍慢于 rg 的是数字和空行。保留逐行字符串构造和输出的情况下，大量命中行仍然昂贵，本实验没有对这部分单独插桩。

多数其他查询变化较小。默认模式的中位数增量最大约 1.24 ms（短词查询）；普通固定字符串的 no-refresh 增量约 0.05 ms。本报告没有进行显著性检验，不把这些小幅变化解释为稳定收益或回退，也不以查询等权平均代替真实 agent 的查询分布。

## 证据与复现

[原始样本与元数据](data/line-matching-2026-09-09/results.json)、[全部逐查询中位数](data/line-matching-2026-09-09/per-query.csv)、[执行脚本](data/line-matching-2026-09-09/harness.py)、[代码差异](data/line-matching-2026-09-09/source.diff)。

复现时，将脚本放入隔离目录，其中放置修改前后的 release 二进制 `before`、`after`，并由 `before index ROOT --index-dir INDEX` 在同目录创建 `index`。按本机情况调整脚本中的 `repo` 与 `root` 路径，然后执行：

```sh
python3 harness.py --iterations 31 --warmup 3 --queries all --output results.json
```

实验只覆盖这份 vLLM 快照，未重新测量其他项目、冷缓存或峰值 RSS。此次匹配语义对齐不代表完整复刻 rg 的所有 CLI 行为；例如显式换行表达式当前不会命中，未加入 rg 对这类表达式的专门错误提示。
