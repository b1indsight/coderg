# vLLM 耗时、内存与索引大小 — 2026-09-07

当前提交 `18c9cc78c332c38d95d70dfade3ca50d9455f23c` 的 release 构建：全量建索引中位耗时 **2.478 秒**，建索引峰值 RSS 中位数 **2.03 GiB**，整个索引目录文件合计 **66.40 MiB**。28 项可比查询中，默认搜索耗时的中位数均值为 **47.75 ms**，rg 为 **71.57 ms**。建索引的内存开销明显高于搜索。

## 环境与测量口径

- Apple M5，10 个逻辑 CPU，24 GiB RAM，macOS arm64；Rust 1.94.0，ripgrep 15.2.0。
- vLLM commit：`569adb5a9780f9c02d22a6b29826acf711512356`；6,835 个文本文件，86,384,180 bytes（82.38 MiB），语料工作区干净。
- 搜索运行开始于 `2026-09-07T09:02:28.980654+00:00`；使用 `cargo build --release --locked`，源码无修改。
- 搜索：30 类正则/固定字符串查询，28 类完整输出与退出码通过 rg 一致性校验；每项、每模式 3 次预热 + 31 次计时，每轮随机交错顺序。输出为文件名、行号和匹配行，计时输出重定向到 `/dev/null`。
- 默认搜索包括 Git/文件新鲜度检查；`--no-refresh` 跳过检查。rg 包含隐藏文件，遵守 ignore，排除 `.git/**` 和 `.coderg-index/**`，不修改线程数。
- 全量建索引：每次使用全新临时目录，1 次预热 + 5 次独立计时；另做 3 次 `/usr/bin/time -l` 峰值 RSS 测量。搜索同样每项、每模式另测 3 次 RSS；内存测量不混入搜索或建索引耗时统计。
- 测量顺序为先搜索、后重复建索引，没有并发运行 benchmark。文件系统缓存为热缓存；没有强制清理系统缓存，结果不代表冷启动。新建索引不等于冷缓存。
- 内存口径为进程峰值 RSS，包含驻留的 mmap 页；不是索引磁盘体积，也不是持续常驻内存。1 MiB = 1,048,576 bytes，1 GiB = 1,073,741,824 bytes。

## 复现

准备相同 vLLM checkout；以下输出和索引路径必须尚不存在。建索引测量脚本会自动删除自己创建的临时索引。峰值 RSS 测量依赖 macOS。

```sh
cargo build --release --locked
python3 benches/regex_suite.py \
  --root /path/to/vllm --binary target/release/coderg \
  --index-dir /tmp/coderg-performance-search-index \
  --output /tmp/coderg-performance-search-results \
  --iterations 31 --warmup 3 --rss-runs 3
python3 benches/results/data/vllm-performance-2026-09-07/index_benchmark.py \
  --root /path/to/vllm --binary target/release/coderg \
  --output /tmp/coderg-performance-index-results
```

归档的 `search/harness.py` 保存本次搜索脚本字节；若使用归档版本，应放回 `benches/regex_suite.py` 的位置以正确定位源码。
