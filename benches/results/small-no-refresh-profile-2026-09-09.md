# 小仓库 no-refresh 快速验证

> 文档状态（2026-09-10）：历史小库查询剖析。最终更新策略和独立查询结果见[三档实测](size-tiers-2026-09-10.md)，下文阶段计时保留为当时的定位证据。

复用 Chromium 临时插桩二进制和分阶段计时方式，在既有 viberwhisper、agentflow 快照上新建独立临时索引。每项预热 5 轮、随机交替测量 31 轮，对比 release、插桩版和 rg。仅测试 `--no-refresh`；不改产品源码。stdout 指向 `/dev/null`，stderr 捕获；计时外验证三种模式完整匹配输出一致。

| 项目 | viberwhisper | agentflow |
|---|---:|---:|
| 查询 | `^impl` | `^class` |
| manifest 字节 | 43,390 | 37,412 |
| release 完整进程 ms | 3.832 | 3.679 |
| 插桩完整进程 ms | 3.833 | 3.807 |
| rg 完整进程 ms | 6.269 | 6.369 |
| 读取 manifest ms | 0.0139 | 0.0142 |
| JSON 解析 ms | 0.0725 | 0.0641 |
| 索引加载合计 ms | 0.1343 | 0.1260 |
| 候选筛选 ms | 0.0086 | 0.0168 |
| 读取候选并匹配 ms | 0.7269 | 0.6348 |
| 候选文件数 | 75 | 63 |
| 命中文件数 | 41 | 52 |
| 匹配行数 | 154 | 198 |

表中时间均为中位数。读取 manifest 加 JSON 解析约 0.08 ms，仅占插桩总耗时约 2%；索引加载整体约占 3%–4%。因此，它不是这两个小仓库查询的主要成本，移除它也只能节省约十分之一毫秒。

已计时的搜索内部阶段合计约 1 ms，与约 3.8 ms 的进程总耗时之间仍有明显差额。差额包括进程创建、程序加载、CLI 初始化、退出清理以及父进程测量开销，不能全部归因为某个尚未单独测量的步骤。文件匹配阶段本身包含 Rayon 初始化和调度。本次不进一步拆解这些固定成本。

这两项查询的 coderg no-refresh 比 rg 快约 1.64×、1.73×；结果仅适用于这些快照和查询，不能代表所有小仓库搜索。
