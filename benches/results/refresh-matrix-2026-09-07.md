# 刷新优化的广泛 benchmark — 2026-09-07

这次扩大到 **7 组语料、102 个查询组合、5 种执行模式**。刷新优化的收益主要出现在文件数量较多的仓库：vLLM 的等语义查询平均耗时下降 **9.9%**，4,096 文件的生成语料下降 **7.1%**，16,384 文件下降 **11.1%**。两个小型真实仓库基本持平。

102 项查询的新版/旧版输出全部一致；其中 100 项也与 rg 一致。初测有 85 项查询的中位数下降、17 项上升。追加复测确认一个小幅回退：viberwhisper 的 `impl` 查询约慢 **0.21 ms（2.8%）**。大量小文件场景的 p95 还出现了尖峰，需要与中位数收益分别看待。

## 测量范围与口径

- 基线为 `403fd12bfc7c612181773ae5fa7a49e87bb045bf` 的 release 二进制；优化版与[上一轮刷新测试](vllm-refresh-2026-09-07.md)完全相同，运行前核对了两个二进制的 SHA-256。本轮没有修改搜索或索引实现。
- Apple M5，10 个逻辑 CPU，24 GiB RAM，macOS 26.6.2 arm64；Rust 1.94.0；`cargo build --release --locked`。
- 每个查询比较旧版默认、新版默认、旧版 no-refresh、新版 no-refresh、rg 五种模式。各预热 3 次、计时 31 次，每轮随机交错执行，共 **15,810 次计时**。每种组合另测峰值 RSS 3 次，共 **1,530 次搜索 RSS 采样**。
- 全量建索引单独计时。每组、每个版本先构建一次预热，再用新目录计时 5 次、测 RSS 3 次；计时包含文件检查、内容读取、建索引和落盘。
- 全部使用热文件系统缓存；每次搜索启动一个新 CLI 进程。计时输出重定向至 `/dev/null`，完整输出校验在计时之外进行。基准进程不并行运行。
- 每组先由基线建立索引供两版搜索共用，前后验证索引文件哈希不变。另行确认新版构建的 lookup/postings 与基线字节一致。
- 对比退出码及规范化后的完整输出：移除可选的 `./` 前缀并排序，保留重复行。语料 Git 状态、二进制和源码在测试前后校验不变。
- 表中的查询耗时是**各查询中位数的等权平均**，p95 是各查询 nearest-rank p95 的等权平均。每行使用自己的查询集，加速比用于该行组内比较。

真实仓库使用固定提交：vLLM `569adb5a9780f9c02d22a6b29826acf711512356`、viberwhisper `ab1f117d922fe06da6fc2f1f72605ba227ba4233`、agentflow `40efd5bcc760bc1aa05029515d2eb46d3dff3c30`。后两者为临时本地克隆，未修改原始工作区。

vLLM 使用原有 30 项正则，加 8 项忽略大小写查询。Rust/Python 各覆盖定义、导入、固定字符串、忽略大小写、分支、宽匹配、短查询和无匹配。生成语料覆盖稀有词的完整行/文件名输出、常见词的文件名/计数输出、分支、忽略大小写、短查询及无匹配。

生成语料均为确定性的 Rust 风格文本，每 64 个文件一个目录，每 97 个文件出现一次稀有标记。三组 64 MiB 语料分别为 4,096 × 16 KiB、16,384 × 4 KiB、64 × 1 MiB。它们的文件数、目录数和 gram 分布均不同；其规律性也高于真实代码，因此索引更紧凑。

## 默认搜索与 rg

以下只汇总与 rg 等语义的查询，单位 ms。变化为新版相对旧版的耗时变化，负数表示更快。

| vLLM（36 项） | 47.94 | 43.18 | **−9.9%** | 71.73 | 33/36 |
| viberwhisper | 8.08 | 8.04 | −0.5% | 7.33 | 0/16 |

| 64 文件 / 64 MiB | 12.37 | 12.12 | −2.0% | 8.38 | 2/8 |

按轮次配对 bootstrap 1,000 次，以上默认搜索汇总变化的 95% 区间分别为：vLLM −10.65%～−9.47%；viberwhisper −1.14%～+0.44%；agentflow −0.28%～+0.70%；small_256 −2.04%～−0.37%；regular_4096 −7.83%～−6.35%；many_small_16384 −11.81%～−9.94%；few_large_64 −3.35%～+0.54%。这些区间描述固定工作负载的计时波动，未做多重比较修正，也不代表其他仓库的效果。

vLLM 相比上一轮四项查询的 15.6% 降幅变小，但绝对节省仍约 **4.76 ms**。更宽的查询集包含更多扫描成本较高的模式，固定开销节省所占比例随之降低。

## 回退与尾部延迟

初测 17 项查询的中位数上升，逐项 bootstrap 区间都包含零。选择涨幅最大的三个点，再加 vLLM 的 `word_sampling` 对照，分别预热 5 次、计时 101 次；以下为这次独立复测：

| 查询 | 旧版 ms | 新版 ms | 变化 | 变化的 bootstrap 95% 区间 |
|---|---:|---:|---:|---:|
| few_large_64 / absent | 6.627 | 6.639 | +0.2% | −3.39%～+3.31% |
| agentflow / word_return | 7.540 | 7.521 | −0.3% | −2.74%～+2.57% |
| viberwhisper / impl | 7.473 | 7.683 | **+2.8%** | +0.20%～+5.34% |
| vLLM / word_sampling | 30.601 | 25.994 | −15.1% | −16.11%～−13.14% |

复测仅计时，在沙箱内执行；主矩阵因系统 RSS 测量权限在沙箱外执行。两轮样本没有合并，绝对耗时分别报告。结果支持保留 Rust `impl` 的小幅回退，另两个主要回退点没有稳定重现。

主矩阵中的 p95 均值如下，单位 ms：

| 语料 | 旧版默认 | 新版默认 | rg |
|---|---:|---:|---:|

| viberwhisper | 9.02 | 8.84 | 8.29 |
| agentflow | 9.29 | 9.30 | 9.30 |

many_small_16384 的 `short_files` 默认 p95 从 205.36 ms 升至 412.23 ms，新版有两个约 412–427 ms 的样本，旧版也有一个约 381 ms 的尖峰。同组 `common_count` 的新版 no-refresh p95 为 384.37 ms，旧版为 176.76 ms。31 样本的 nearest-rank p95 是第 2 大样本，因此少量尖峰会显著影响统计。原始样本全部保留。

再针对这两条路径分别预热 5 次、随机交错计时 201 次，结果如下。这也是独立的沙箱内计时，未与主矩阵合并：

## 当前明显落后于 rg 的场景

- vLLM 数字查询：新版 **154.71 ms**，rg **95.97 ms**；TODO 注释查询为 **101.05 vs 68.54 ms**。
- 64 个大文件的常见词 `-l`：新版 **16.98 ms**，rg **7.20 ms**；短词 `fn -l` 为 **16.44 vs 7.38 ms**。
- 小型真实仓库中，默认搜索固定成本约 8 ms，当前索引收益不足以普遍抵消这部分成本。

从 [match_file](../../src/search.rs#L167) 实现看，`-l` 仍先建立整份文件的行起点，并收集匹配行后才返回。对只需确认文件命中的调用，这里有可避免的工作，值得作为下一步单独测量的优化点。刷新检查仍为完整文件遍历，文件数量增长带来的成本也继续存在。

## 正确性、Git 状态变化与证据

102 项查询与基线全部一致。与 rg 不同的只有 vLLM 的 `async_def` 和 `blank_lines`，分别多 4 行和 6,440 行，均为已有语义差异；上述 rg 性能比较已排除这两项。

Git 状态变化复用同一对二进制已完成的 [7 种场景、11 次计时及 3 次 RSS 测量](vllm-refresh-2026-09-07.md)：单文件修改、提交推进、32 文件直接提交、同树提交、缓存回退及前后的干净搜索。该证据未重新计入本轮矩阵样本。原有 22 项 Rust 测试与上一轮 Clippy 结果仍适用于相同的搜索实现；新基准脚本先经过两组语料的小样本试跑，再执行完整矩阵。

执行入口为 [refresh_matrix.py](../refresh_matrix.py)。`plan.json` 指定冻结语料路径和类型，索引与输出目录必须在语料外；脚本会清理自己创建的索引，保留测量和日志：

```sh
python3 -B benches/refresh_matrix.py \
  --plan /path/to/plan.json --baseline /path/to/baseline \
  --binary target/release/coderg --output /path/to/new-results \
  --iterations 31 --warmup 3 --build-iterations 5 --rss-runs 3
```
